The loop

Ask, plan, build, verify.

Most agents start typing immediately. Nomin stops to work out what it is missing, shows you the plan, and only then touches the codebase.

01

It asks

Nomin surfaces the decisions it can't make for you — stack, scope, tone, constraints — instead of guessing and building the wrong thing.

02

You approve

A written plan lands before any work starts. Edit it, cut it down, or send it back. Nothing runs until you say so.

03

It builds

Files, tests and the running app — produced in one continuous session, with the canvas open so you watch it take shape.

04

It verifies

Every claim is checked against real evidence — a test run, a request, a rendered page. Anything unproven is labelled unverified.

Why it finishes

Built for work that takes longer than one reply.

Survives rate limits

Long builds don't die halfway. Nomin holds the thread across limits and resumes exactly where it stopped — same plan, same context.

Evidence, not assertions

"It works" isn't good enough. Nomin attaches the test output, the response, the screenshot — or marks the claim unverified and tells you.

A live canvas

The build renders next to the conversation. Watch the page appear, click through it, and redirect mid-flight instead of reading a diff.

Pick your effort

Balanced by default. Push to deep reasoning when the problem earns it, or drop to fast when you already know the shape of the answer.

Speak, show, or paste

Dictate a brief, talk it through live, drop in an image, a video, a file — or point the camera at a whiteboard and let Nomin read it.

Keyboard first

The command palette reaches every session, every setting and every file without lifting your hands off the keys.

Verification

Nothing ships on the word of a model.

Trion 1.5 can make mistakes. So Nomin treats its own output as a claim to be tested, not a result to be trusted — and shows you the receipts.

  • Tests are run, not described — you get the actual output.
  • Endpoints are called and the real response is attached.
  • Pages are rendered and checked before they're called done.
  • Anything it couldn't prove is flagged unverified, in plain sight.

The standard

Every build is held to the same bar.

Not a style guide you have to remember to ask for. It ships with every brief.

Real copy everywhere

No lorem ipsum. No “Feature one / Feature two”. No empty sections left as headings.

One type scale, one accent

A single scale, held throughout. One accent colour, used sparingly.

Responsive from 360px

Nothing overlapping, nothing clipped, no horizontal scroll — at any width.

Accessible by default

Real landmarks, alt text, visible focus rings, and at least 4.5:1 contrast on body text.

Motion that explains

Animation only where it clarifies something, and never longer than 400ms.

Nothing decorative that lies

Every control does something. A button that does nothing is a bug, not a placeholder.

The platform

Trion 1.5, and the API around it.

Expand any row for the detail.

Trion 1.5 is tuned for long, interruptible engineering sessions rather than single-shot answers. It holds a plan across hours of work, survives rate limits without losing context, and is trained to stop and ask rather than guess when a requirement is missing.

It can make mistakes. That is exactly why verification is not optional — every claim is checked against real evidence before it is presented as done, and anything unproven is labelled.

  • ContextHolds the full plan, file tree and conversation across a session.
  • ModesFast, Balanced, Deep — pick the effort the problem deserves.
  • MultimodalReads images, video, audio, files and live camera input.
  • ResumptionContinues through rate limits from the exact step it stopped on.

Open a session, stream the plan, approve it, and collect the evidence — programmatically. The API exposes the same ask → plan → build → verify loop the workspace uses, so anything you can do by hand you can automate.

from nomin import Nomin

client = Nomin(api_key="nmn_...")

session = client.sessions.create(
    brief="A dashboard for build sessions",
    mode="balanced",
)

# The plan arrives first — nothing runs until you approve it.
plan = session.await_plan()
session.approve(plan.id)

for step in session.stream():
    print(step.status, step.evidence)
import { Nomin } from "nomin";

const client = new Nomin({ apiKey: "nmn_..." });

const session = await client.sessions.create({
  brief: "A dashboard for build sessions",
  mode: "balanced",
});

// The plan arrives first — nothing runs until you approve it.
const plan = await session.awaitPlan();
await session.approve(plan.id);

for await (const step of session.stream()) {
  console.log(step.status, step.evidence);
}
# Create a session
curl https://api.nomin.dev/v1/sessions \
  -H "Authorization: Bearer $NOMIN_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"brief":"A dashboard for build sessions","mode":"balanced"}'

# Approve the plan, then stream the run
curl https://api.nomin.dev/v1/sessions/$ID/approve \
  -H "Authorization: Bearer $NOMIN_API_KEY" -X POST

curl -N https://api.nomin.dev/v1/sessions/$ID/stream \
  -H "Authorization: Bearer $NOMIN_API_KEY"
